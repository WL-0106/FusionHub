# FusionHub 仪器模块开发规范

> 本规范是「后续新增仪器仪表上位机」的硬性约束。新模块接入前**必读**，违反以下条目会导致界面走样、框架功能失效或现场安全风险，一律不得合入。

---

## 一、模块接入契约（必备）

每个模块目录必须提供 `__init__.py`，并导出两个函数：

```python
def create_page(parent=None) -> QWidget:
    """构造可嵌入主窗口的页面。"""
    page = XxxPage()
    if parent is not None:
        page.setParent(parent)
    page.setMinimumSize(0, 0)
    page.setSizePolicy(QSizePolicy.Expanding, QSizePolicy.Expanding)
    return page

def shutdown(page):
    """退出/卸载时：断开链路、停止轮询与工作线程、释放高危输出。"""
    if page is None:
        return
    try:
        page.shutdown()
    except Exception:
        pass
    try:
        page.close()
    except Exception:
        pass
```

要点：
- 模块自行 import 所需的 `instrument_hub` 公共设施，不要依赖主窗口注入。
- `shutdown` 必须真正回收：停掉所有 `QTimer`、`QThread.wait()`、关闭串口/套接字，高危输出（电源/拉载/高压）必须先安全关闭再断开。

## 二、UI 硬性规则（本次沉淀，后续禁止再犯）

### 规则 1：所有下拉框必须有下拉箭头 ▼

**问题**：对 `QComboBox` 一旦在 QSS 里设置了 `border`，Qt 就不再绘制默认下拉箭头，必须显式提供 `QComboBox::down-arrow` 的 `image`。

**规范做法**：

```css
QComboBox { border: 2px solid #E4E2F3; border-radius: 9px; padding: 5px 10px; }
QComboBox::drop-down { border: none; width: 22px; }
QComboBox::down-arrow { image: url(<绝对路径>/arrow_down.png); }
```

三条铁律：
1. **设了 `border` 就一定要补 `down-arrow` 的 `image`**，否则箭头消失。
2. **禁止用 CSS 三角法**（`border-top` + 两侧 `transparent` + `width/height:0`）——Qt 的 QSS 在 `::down-arrow` 子控件上会把 `width:0/height:0` 拉伸成**实心矩形**，不是三角。
3. **只保留单条 `down-arrow` 规则**，禁止再加 `:hover` / `:disabled` 等伪状态变体，否则 Qt 会双重绘制出「幽灵箭头」。

**箭头资源**：用 Pillow 生成 16×16 透明底三角 PNG，颜色取主题主色（全局 `#4F46E5`，it8500 橙 `#e8721f`），`LANCZOS` 抗锯齿。路径必须经 `_asset()` 解析，兼容开发态与 PyInstaller 打包态（`_MEIPASS`）：

```python
def _asset(name: str) -> str:
    base = getattr(sys, "_MEIPASS", None) or os.path.dirname(os.path.dirname(__file__))
    return os.path.join(base, "assets", name).replace("\\", "/")
```

### 规则 2：表单布局禁止「固定宽输入框列 + 该列 setColumnStretch」

**问题**：QGridLayout 里若给某个放有 `setFixedWidth` 固定宽输入控件（QLineEdit/QSpinBox/QComboBox）的列设 `setColumnStretch`，输入框不跟着拉伸，富余空间会全部落在输入框**右侧**，表现为「标签贴最左、输入框悬在中右、中间大片空白」的割裂感。

**规范做法**（每行 2 组参数的表单）：

```
[左弹性 | 标签 | 输入框 | 固定分隔 | 标签 | 输入框 | 右弹性]
```

- 标签列、输入框列**一律不设 stretch**（保持紧凑，标签紧贴输入框）。
- 富余宽度交给**左右两侧的弹性列**（各 `stretch 1`）或**中间的固定分隔列**承接，让整组参数居中、两组之间留固定间距（约 32px）。
- 输入框用固定宽即可（约 160~170px），字号/高度由全局主题统一。

**判断口诀**：`setFixedWidth 的输入控件，它所在的列绝对不能 setColumnStretch`。反之，若输入框**不固定宽**且希望它填满剩余空间，给该列设 stretch 是**合理**的（如 it8500 设定值框、serial_debug 发送值框）。

### 规则 2b：通讯连接区优先用「按语义分组的 QHBoxLayout 行」，不要用多列 QGridLayout

**问题**：连接区参数多（通讯方式/串口/IP/端口/波特率/数据位/停止位/校验位/地址/连接/断开），若塞进一个多列 QGridLayout，会出现两个连锁坑：

1. **列宽互相牵连**：Grid 里同一列的控件会被拉成该列最宽控件的宽度，导致本应不同宽度的控件（如下拉框 vs 按钮）变得一样宽；
2. **固定宽失效**：`setFixedWidth` 只设 max，但全局 QSS 给 QComboBox 设了 `min-width:90px` + padding，实际渲染宽度会超过固定值，进一步加剧列宽牵连。

结果就是「标签与输入框间距失控、行尾大片空白、刷新/断开按钮被拉成 130px 宽」。

**规范做法**：按语义拆成多个 `QHBoxLayout` 行，每行「标签紧贴控件 + 单元间统一 8px + 末尾 `addStretch(1)`」：

```python
top = QHBoxLayout()
top.setSpacing(8)
top.addWidget(QLabel("通讯方式"))
top.addWidget(self.cmb_mode)      # 每个输入控件都 setFixedWidth 真实固定宽
top.addWidget(self.btn_refresh)
top.addStretch(1)                  # 富余空间推到行尾
g.addLayout(top, 0, 0)
```

要点：
- 逻辑上属一组的参数放一行（如「链路行」放通讯方式/串口/刷新/IP/端口/连接，「协议参数行」放波特率/数据位/停止位/校验位/地址）。
- 需要按模式显隐的参数（TCP vs 串口 vs 模拟），用 `setVisible` 控制，HBox 下隐藏后控件**自动前移**，不会残留空洞（比 Grid 的「隐藏列留空」更干净）。
- 每个输入控件都显式 `setFixedWidth`（给真实固定宽，别只给 `setMinimumWidth`，后者会被列宽拉伸）。

### 规则 3：连接按钮遵守框架契约 objectName

框架靠 `objectName` 判断连接态并点亮绿色指示灯：

- 初始（未连接）：`btn_connect.setObjectName("btnConnect")`
- 连接成功：`setObjectName("btnConnected")` + `setText("已连接")`
- 断开：还原 `setObjectName("btnConnect")` + `setText("连接")`

不要自定义 `greenBtn` / `success` 等脱离契约的 objectName，否则框架绿灯永远不亮。

### 规则 4：高危动作必须二次确认

电源开输出、电子负载拉载、耐压/绝缘测试启动、继电器闭合等**高危动作**，`on=True` 分支必须先弹 `ConfirmOutputDialog`（或等价确认框），用户取消时回滚开关勾选态。退出/卸载（`shutdown`）时，断链前必须先显式关闭高危输出（如 `set_input(False)`、`set_output(False)`），避免断电后设备仍处于危险状态。

### 规则 5：退出清理完整闭环

`shutdown` / `closeEvent` 必须停止**所有**定时器与线程：
- 轮询、心跳、看门狗、离线检测、扫描等每个 `QTimer` 都要 `stop()`；
- 每个 `QThread` / 工作线程都要 `wait()`；
- 不要每次操作新建短命线程（`threading.Thread(...).start()`），改用常驻单工作线程 + `queue.Queue` 任务队列，任务天然串行、退出可干净 join。

## 三、文案与命名规范

- 主题统一为「统一浅色主题」，禁止残留「深色主题」「永联风格」等旧描述。
- 按钮文案必须与实际功能一致，占位功能（协议未确认的命令）必须**禁用并标注「待协议确认」**，不得误导现场操作。
- 不写死随状态变化的 UI 文案；随选项联动的行（标签+输入框+单位+按钮）要整体联动。
